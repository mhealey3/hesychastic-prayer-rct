# Hesychastic Prayer RCT — Analysis Pipeline

Analysis code for a three-arm longitudinal randomized controlled trial comparing
Hesychastic Prayer (HPrayer), Loving-Kindness Meditation (LovingKindness), and a
Control condition. The study has intake (T1) and outtake (T2) timepoints plus
twelve weekly check-ins (T1a–T6b) for the two active arms.

**This repository contains code and documentation only. It does not contain
participant data.** Data is stored separately (see "Getting the data" below).

**Attribution.** Data collection, cleaning, scoring, and compilation were carried
out by Morgan Healey (mrhealey@bwh.harvard.edu OR morgan_healey@alumni.brown.edu) with assistance from Claude (Anthropic) under the supervision of PI
Michael Ferguson (mferguson@bwh.harvard.edu). Any use of this work or the

## Getting the data

**Participant data is not stored in this repository.** It is stored in the
project's BWH Dropbox folder. Collaborators are given access to that folder
directly (by institutional account); if you need access, contact:
mhealey@bwh.harvard.edu or mferguson@bwh.harvard.edu.

Once you have Dropbox access, download the files and place them into the local
folder that matches each file's **type**, so the scripts run as written with
their file paths (which resolve via here()).

| File type | Destination folder in the repo |
|-----------|--------------------------------|
| SAV files (intake, outtake, and weekly check-ins) | SAV files/ (weekly files under SAV files/Weekly/) |
| Excel files (e.g. weekly T1a) | Excels/ |
| Condition assignment CSVs (Control, HP, LK) | Group assignments/ |

The administered survey instruments (e.g. the official intake questionnaire) are
in the Dropbox; they are the reference for verifying scale scoring
against what participants actually saw.

After the data folders are populated, open Hesychastic Prayer.Rproj in RStudio
and run the scripts in order.

**Note on data handling:** participant data must never be committed to this
repository or moved to GitHub. Keep it in the BWH Dropbox; the repo is code only.

## Pipeline order

The scripts must be run in order — each depends on the previous one's output.

1. **01_cleaning.R** reads the raw intake/outtake SAV files and the condition
   assignment CSVs, and writes the cleaned analytic sample to
   Outputs/1_cleaned_hp_dataR.rds (N = 484: HPrayer 194, LovingKindness 193,
   Control 97). It also writes Outputs/flow_counts.rds (CONSORT counts).

2. **02_create_composites.R** reads script 1's output, scores the outcome
   scales, and writes Outputs/02_cleaned_data_with_composites.rds (the cleaned
   sample plus the scored T1/T2 outcome composites).

3. **03_weekly_processing.R** reads the weekly check-in files *and* script 2's
   composite dataset. It produces the weekly affect composites, a participant-
   level wide table, the attrition/participation matrix, and a per-participant
   adherence measure joined to the outcome data. Outputs:
   - **03_outcomes_with_adherence.rds / .csv** — the primary analysis-ready
     table: the full cleaned sample (N = 484) with the scored T1/T2 outcome
     composites plus each participant's weekly adherence (weeks_completed and
     pct_completed). Adherence is 0 for treatment participants who completed no
     weekly practice and NA for Control (who were never assigned the practice).
   - **weekly_wide.rds** — one row per weekly participant (N = 379), with each
     week's affect composites and a-session content as separate columns tagged
     by timepoint (e.g. PRE_PA_T2b = pre-practice positive affect at week 2b).
     For cross-week / participant-level analysis.
   - **attrition_matrix.rds / .csv** — one row per enrolled treatment
     participant (N = 387), one column per timepoint (T1a–T6b), each cell 1 if
     the participant completed that week's practice, else 0. Never-starters and
     non-completers appear as 0. This is the participation record behind the
     attrition curve and the adherence measure.
   - **weekly_scored.rds** — the 24 per-week tables (one per timepoint × arm),
     each with its raw items and scored affect composites. Stored as an R list,
     accessed by name (e.g. weekly_scored[["T2b-HP"]]). For per-week or
     item-level analysis.
**Figure generation (run last):** flow_diagram.R produces a CONSORT flow
diagram. It reads outputs from *both* 01_cleaning.R (flow_counts.rds) and
03_weekly_processing.R (attrition_matrix.rds), so run it after scripts 1–3.
Output: Diagrams/consort_flow.pdf and .png.
   

   **File formats.** The .rds files can only be opened in R
   (readRDS(here("Outputs", "weekly_wide.rds"))); they are not spreadsheets and
   will not open in Excel. weekly_scored is provided only as
   .rds because they preserve R-specific structure (haven value labels, and
   weekly_scored is a list of tables). The outputs that also have a .csv version
   open in any spreadsheet program, but .csv does not preserve value labels.



Each pipeline script has a companion decisions document in Documentation/
recording the methodological choices and their rationale.

## Requirements

- R (version 4.4.2)
- Packages: haven, readxl, readr, dplyr, tidyr, stringr, purrr, here, ggplot2,
  afex, emmeans, consort. (The tidyverse is loaded as individual packages, not
  the bundle.)
- All file paths use here() and resolve relative to the project root, so open
  the project via Hesychastic Prayer.Rproj (or set the working directory to the
  project root) before running anything.

## Data handling summary

- **Code and documentation** live here on GitHub (private repository).
- **Participant data and survey instruments** live in the BWH Dropbox, shared
  with collaborators by their institutional accounts.
- The .gitignore excludes all data file types (.sav, .xlsx, .csv, .rds) so data
  cannot be accidentally committed. This keeps the repository free of participant
  data and preparable for an eventual de-identified public release.
- Any public data release must be a separately prepared, de-identified
  derivative reviewed and approved through the study's IRB — never the working
  data files.
